# SOLWEIG-light optimization: lean, branch-local operating rules

Use `optimization_v4/PLAN.md` and `TASKS_OPTIMIZATION.yaml` once; workers read only their dossier and assigned code/tests. This user-requested v4 cadence supersedes v3's proposed repeated large tests and release-matrix-before-handover instructions, not numerical/API/scientific contracts or existing protected-branch requirements.

Create an isolated local `perf/lean-cpu-v4` integration branch/worktree from current HEAD, preserving user changes. Reviewed worker commits may enter that branch, never main. No automatic push, PR, main merge, release, destructive cleanup or reset. Finish with a merge-review packet; the user decides when to merge.

Use L0 tiny proof/guard checks; L1 actual-kernel fixtures normally <=128 per side; L2 real 64-128-square TIFF pipeline with 24/48 chronological steps; L3 128/256-square timings only for shortlists. Keep full patch count and required physics for each fixture. No routine 1024-scale run during development. One combined final candidate gets L4 actual 24 x 1024-square evaluation after freeze. Never launch a full-batch test per worker, family, commit or CI push.

No blanket full-suite/wheel rebuild after every edit. Reuse valid evidence only with its complete source/transitive-dependency/test/fixture/reference/environment/profile identity. Rerun affected small checks after coherent behavioral changes. Preserve failures, boundary tests, all carried state, categorical/raw payloads and fallbacks. Small validation is not a large performance claim.

Astra owns initial portfolio, real semantic decisions and final review. Delegate bounded implementation/debugging to supported Luna Max or an available suitable equivalent; record actual model/effort. Mechanical tasks use lower effort. At most four sessions; no recursive agents; no worker/LLM progress polling. Use completion events or supported blocking waits. Workers implement/test/repair autonomously and return <=350-word terminal evidence summaries. Reviewers inspect valid results without reflexive reexecution.

One integrator owns shared engine/pipeline/API/schema/status. One evidence owner runs exclusive L3/L4 timings, with no competing local builds/tests. Only this owner can release final-scale execution after source freeze. Independent numerical review and process watchdogs remain mandatory.

Preserve all seven workflows, Torch-free core, typed arithmetic, existing explicit FMA, fastmath=False, original per-receiver patch/ray order, first-step/bush/border behavior, visibility value 2/raw bits, water mutation and chronological state. No reduced final resolution/timesteps/patches, surrogate, relaxed tolerances or weaker durability. Candidate code never produces upstream goldens.

CI default is local-only development with no pushes. If a PR is later requested, keep a small real CPU end-to-end gate and required checks; heavy optional matrices are explicit campaigns. Do not globally disable CI or force green skipped checks. See `BRANCH_AND_CI.md` before any remote action.

Stop at an honest review-ready branch. One final runtime observation is `target_demonstrated_once`, not a robust speedup or Section 13/P7/P8 release certificate. Missing or deferred gates stay visible. After a failed final run, fix via small reproductions; at most one causally justified final retry is preauthorized. Do not enter an unbounded expensive validation loop.
