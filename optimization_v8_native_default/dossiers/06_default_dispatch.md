# Qualified auto-default selection

## Default is not forced-native

The standard call remains unchanged. After gates pass, env-unset mode uses a tiny private deterministic selector. Rows specify supported artifact ABI/ISA/math/scalar/input/resource domains with measured crossover. Missing/unqualified rows run Numba. The output and operational contract is independent of selected row.

For the former native-only single-thread large-block win, do NOT add a table saying all H/B use native. B7-60 disproves that promotion. New qualifying evidence must cover ordinary default H/B and the region planner's actual execution granularity.

## Decision hierarchy

1. Resolve user expert override once per workflow, preserving legacy recognized/unknown behavior.
2. Validate source-independent installed artifact capability once, before numerical work.
3. Match math profile/scalar ABI/demand scope and owner/stride/layout contracts.
4. Obtain actual CPU reservation and bounded workspace; choose a supported scheduling row.
5. Match workload-size/chronology/cache criteria against prequalified policy.
6. Prepare native handle and leases. Otherwise return the original verified Numba region with a structured internal reason.
7. In execution, unsupported data not covered by a precondition must have been rejected before native writes. Errors after launch propagate, not hidden fallback.

No mandatory runtime benchmarking, black-box ML predictor or device driver installation. Policy introspection can be private/debug-only so normal stdout/CLI remain unchanged. A release may contain only one native-qualified platform and Numba elsewhere; this is honest partial acceleration, not platform failure.

## Policy provenance

Each row points to immutable source/build/math identity, actual installed-wheel test report, primary evaluation cells, paired data, independent review and coverage counts. Policy generation is not itself proof. The policy must be reviewed together with dispatcher code and kept out of geometry identity if it cannot change numerical geometry. Simulation/checkpoint provenance records effective implementation.

Certificates are created only after results, but the criteria and test split are frozen before candidate results. The repository must not ship example rows with placeholder success. This packet ships only pending templates.

## Error taxonomy

- Not shipped / unsupported OS or ISA / no qualified profile / workload too small / reserved-memory shortage: auto decline to Numba before launch; normal use stays quiet and functional.
- Hash/ABI mismatch in optional artifact: never execute it; auto can quarantine/decline with recorded reason. Explicit native request reports failure. Distinguish broken packaging in release evidence even if fallback works.
- Native numerical mismatch, illegal instruction, OOM after admission, worker crash: failed native path. Do not suppress it with post-launch retry. Preserve transactional recovery and require repair before promotion.
- Candidate-only user data validation difference: use original path for unsupported domain and test error equivalence; do not silently accept malformed input.

## Must-pass tests

Native-qualified wheel, ordinary call, all backend env unset: actual native work >0 and expected coverage, exact outputs/state, same public surface. Missing binary, no compiler, wrong architecture, unqualified math, unknown env and explicit numba: original path correct. Explicit native unsupported-input fallback counts and build failure semantics distinct. Concurrent tile processes cannot race generation changes. Read-only site-packages and native dev cache disabled do not affect auto.

Default eligibility remains narrower than build capability. Do not enable cells solely because a smoke test passes or an instruction set is present. Performance portability requires per-class evidence.
