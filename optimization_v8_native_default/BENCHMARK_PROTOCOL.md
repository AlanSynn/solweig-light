# Measure the new region and the unchanged user entry

## Freeze before evaluating new variants

Create one versioned protocol referencing current A0/M0 source hashes, input generator/corpus hashes, raw capture metadata, dependency/compiler/math profile, target hardware/thermal/power conditions, exact CPU and memory budgets, flags/checkpoint policy, tuning/held-out split and PROMOTION_POLICY. Existing B7-60 values are historical evidence, not fresh matched controls.

Use full 24/48 chronological records in small spatial fixtures. Primary target P=153. Guard tests can vary B/P to test indexing, never reduce final workload for speed. A medium motif is a synthetic/development case and cannot represent the actual 24-tile corpus.

## Timing boundaries (record all; do not substitute)

1. `leaf_kernel`: prepared native pointers/arrays, synchronous result; no claim of application gain.
2. `region_total`: checks, owner leases, decode, exact classifier, layout, pool dispatch, two sweeps, synchronization, output placement; all costs required per execution included.
3. `workflow_warm`: real public API/CLI over prepared unchanged geometry, all output/checkpoint work included, native artifacts already installed. Record residual startup.
4. `workflow_first_use`: start before required imports/initialization for that deployment profile; include validation, preparation, geometry and durable publication. Build a release wheel before this timer, because end users receive it; old dev-build time belongs to a separately labelled dev case. Do not subtract imports for candidate while retaining them for baseline.
5. `target_campaign`: actual K=24 spatial tiles, 24 records each, actual extents/overlap/resolution, frozen flags and total resource envelope, artifacts complete.

Measure lazy/native completion rather than enqueue time. Keep instrumentation and uninstrumented timings separate. Run in independent processes for H changes and verify actual Numba/native pool sizes inside tile children, not just env strings.

## Controls

A0 current accepted runtime. B1 new layout/producer/region in Numba. C1 same layout with native. Optional C0 loader-fixed leaf explains regression but does not replace A0/B1 controls. Compare same outputs, scalar profile, cache regime, hardware budget and IO boundaries. Main and upstream comparisons get their own identities and tables.

No 'C1 single thread / A0 four threads' cell is named matched 4-thread performance. It is either a lower-resource diagnostic or a scheduler design test whose complete budget is recorded. Same-thread method and same-budget throughput are different comparisons; keep both explicit where useful.

## Small evaluation matrix

Tuning: one 64-square dense and one vegetation fixture, short kernel repetitions. Held-out: small actual TIFF scenes at 128/256 square, dense/vegetation, ordinary default and supported H/B. Native call tails and f64 profiles from real captures matter more than giant synthetic f32 blocks. A test on default B=128 must not silently call B=65536 under a changed public parameter; internally aggregated dispatch is allowed only with exactness proof and included scratch.

Triage uses two alternating pairs; finalists three pairs. Use A/C, C/A order or a frozen randomized schedule and preserve raw data. Do not run dozens of candidates on all large cases. Admit a candidate to full pipeline only if region cost coverage can materially change total time. Paired median ratios and aggregate geometric means are labelled observed small-sample summaries, not significance claims.

A memory-pressure kill is a failed/censored run. A retry does not erase it. Quiet-host monitoring is read-only and may not terminate unrelated user applications. Delay or mark uncertainty rather than consuming unlimited experimental runs.

## Native execution proof

At actual C entry increment counters for completed pixel-patch work, call counts, scalar/layout/profile and artifact generation. Include pre-launch fallback and errors separately. Build stamps or a loaded module alone do not prove execution. Record full coverage and all source origins from installed site-packages. Timing runs may use low-overhead aggregated counters; detailed per-call timers stay in separate diagnostic runs.

## Memory and IO

Sample the process tree with correct OS units and descendants; report potential RSS double-counting of shared pages separately from admission. Include native arena, NumPy intermediates, GDAL caches, subprocesses, queues, mapped working set and host pressure/swap. Parent ru_maxrss alone cannot qualify memory. No 4-worker configuration is admitted based on the 0.23GiB parent record.

Count logical vs actual DRAM/IO bytes distinctly. Post-run hashing may be outside the declared application boundary only when it is independent evidence analysis; existing in-application integrity validation stays inside. Stable output digests do not excuse deleting required durable operations.

## Scale budget and default promotion

No worker runs 1024 per edit. After local candidate freeze, select ONE final large workload: actual 24-tile corpus if present and qualified; otherwise the existing 4-tile synthetic scale guard, explicitly not actual-target. Default budget: one candidate run, zero new large baselines when valid matched evidence exists; at most one justified fresh A/Baseline run if needed to compare the new boundary, and at most one causal candidate retry after a small reproducer/fix/re-freeze. No repeat-seven-slot campaign by habit.

A local small-default promotion may be reported with actual-target unverified. A broad scale claim needs the scale evidence. Final env-unset candidate must use the packaged allow-list and cannot be a forced-native benchmark disguised as user default. Keep final baseline override only inside the benchmark harness, not user instructions.
