# Native-default continuation rules

Continue the existing `perf/native-optimization` branch. Preserve user work; detached worktrees at exact bases are allowed. No push/PR/main merge/release/automatic hosted CI. Only integrator changes shared API/dispatch/packaging files.

Goal: meaningful native automatic default with main-compatible installation/API/CLI/outputs. Ordinary users need no native env/extra/compiler/runtime download. Shipped platform wheels accelerate qualified scopes; source/no-native installs retain Numba without new requirements. Do not claim fallback execution as native success.

Preserve typed arithmetic, ordered reductions, f64 surface chains, raw bits, state chronology and durability. Native unsupported domain declines before launch; admitted failure is not hidden by fallback. Current Numba A, equivalent-layout Numba B and native C are separate controls.

Read PLAN, DX_CONTRACT and the relevant dossier, not every historical packet. Implement, test, repair and independently review without user approval loops. Delegate freely; do not poll worker transcripts. Local resources remain bounded; benchmark owner is exclusive. Small real tests first, final large workload last. No theoretical or packet-tool result is a measured speedup.

Defaults are enabled only after PROMOTION_POLICY and installed no-env tests pass. If native loses, keep useful B/A improvements and report native default incomplete. Keep task/evidence state current. No Astra invocation is needed.
