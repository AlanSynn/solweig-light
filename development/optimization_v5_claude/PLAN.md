# Claude Code execution plan v5

## Mission and endpoint

Implement an exact/guarded CPU optimization portfolio using GLM-5.3 coordination and verified Opus specialists/reviewers where available. No runtime Astra/Codex handoff is required. The design is supplied by `DESIGN_AUTHORITY.md`, `IMPLEMENTATION_BLUEPRINT.md` and the complete inherited mathematical catalog. Focus on execution, not recreating this design from scratch.

Target: 24 actual 1024-square logical tiles, 24 chronological timesteps and 153 patches, <=1800 seconds under frozen local CPU/RAM/storage and unchanged inputs/outputs/durability. Aim analytically for 1200-1380 seconds as margin, not a promised runtime. Final large candidate trial is one by default. Development remains small. Finish on an unmerged optimization branch with honest scope; do not claim P7/P8 or old Section 13 release completion.

## Phase A: one setup, explicit routes and baseline

1. Coordinator reads the applicable repository instructions, `DESIGN_AUTHORITY.md`, this plan, `MODEL_ROUTING.md`, `VALIDATION_POLICY.md` and the task DAG once. Do not bulk-load all evidence or every proof into every worker.
2. Record actual HEAD and user worktree changes. Create `perf/claude-glm53-cpu-v5` in a separate worktree from the actual intended commit, with a unique suffix if needed. Keep prior optimization work; never reset to the historical snapshot automatically. A dirty checkout is not license to stash or discard changes. Essential uncommitted dependencies need an explicit safe snapshot treatment.
3. Establish the GLM execution profile. Establish a real Opus route separately; see the alias trap in `MODEL_ROUTING.md`. No global settings overwrite, raw secret logging or automatic provider installation. Native same-provider delegation and isolated cross-provider sessions are different capabilities.
4. Install only the small project rules and needed `.claude/agents` templates using the preview-first helper or equivalent careful edits. Worktree base, dependency installation and instructions must be verified for every worker; code agents must not accidentally branch from main.
5. Reuse source-bound reference artifacts, environments and existing small fixtures. New candidate code never generates its own golden. Inspect final dataset headers/manifests if available, without a large simulation or repeated full copy.

Outputs: source/route/capability inventory, immutable baseline identity, local integration worktree, lean validation protocol, shared resource budget and evidence paths. A missing provider blocks only that route, not every local task. A missing real target dataset blocks an actual-target claim, not kernel work.

## Phase B: broad independent preparation, narrow performance selection

Dispatch every useful ready task that has disjoint write ownership and acceptable local resource cost. There is no hard four-agent cap. Suitable concurrent preparation includes: source/dispatch census, sky proof, radiation expression inventory, GVF dependency audit, memory-lifetime inventory, actual-kernel fixture design, branch/compatibility review and throughput-model setup.

Proof-only agents do not run full test suites. Fixture agents write only new owned test files. Implementation owners consume stable interface contracts. Same-file alternative implementations use separate worktrees and isolated new modules, not concurrent edits to one production path.

The one lab owner measures a representative 128/256-square baseline and records non-overlapping stage times plus ray/decode/copy/cardinality/workspace counters. This is not a 1024 admission. Use the small census to choose first variants and later activate conditional catalog entries. Do not launch a 56-way coding contest.

## Phase C: independent first-wave implementations

### C-R: rays

First add guarded non-first-step absorption to the existing SVF pixel path, preserving its original state and output finishing. Separately evaluate suffix certificates, Boolean state projection, existing parallel dispatch and SVF-consumption fusion. Do not apply an SVF proof to wall-height results. Positive-bush remains the old path until the dedicated R04 proof/counterexample work is accepted.

### C-P: radiation

Start with one consumer and one ordered kernel. Separate loop/layout/decode fusion from exact categorical expression preevaluation so their effects can be attributed. Cache exact geometry-only tangent/angular factors only with profile/ownership guards. Preserve independent low-level `diffsh`, mixed dtypes, raw codec, signed zero/nonfinites and original patch accumulation order. The next stable patch may fuse `aniLum` only after the integrator's dataflow review.

### C-G: ground view

First isolate source preparation and first/later water snapshots. Then fuse gather and receiver postprocessing. Keep a trace/reference entry to expose the 16 intermediate values for small differential checks. Prefix/repeated-add replay and static unshadowed fields follow only after prefix/material census and their preparation cost are known.

### C-S: systems

Use actual stage lifetimes and encoded metadata to improve memory admission without discarding raw fallback/native reserve. Introduce bounded persistent tile workers with per-tile cleanup and deterministic failure propagation. Coordinate worker/thread/block settings globally. Do not introduce a distributed service or time-axis parallelism.

Each family validates L0/L1 after a coherent patch, then L2 for affected chronological interactions. The independent reviewer checks proof, concrete typed code and existing evidence. They do not rerun every passing command for reassurance. Review/repair completes inside Claude Code without a routine call back to this chat.

## Phase D: controlled integration and small shortlist

Only the integrator owns `engine.py`, `pipeline.py`, shared public dispatch, comparison manifests and central status. Workers deliver immutable commits plus integration recipes. Integrate onto the optimization branch in recorded order, keeping accepted alternatives available as fallbacks. Review refers to an immutable source identity, not an evolving branch name.

Run only affected small cross-family interactions and one stable installed-wheel pipeline check. L3 belongs to the lab owner: 128/256-square, 2-4 small tiles, a compact predeclared resource grid, at most two runtime variants per family and no automatic repetition explosion. Unlimited remote inference may explore more proof ideas, but it does not expand the L3/L4 budget.

On actual residuals, activate selected second-wave tasks: input-only bush controls, exact ASVF/signature reuse, certified classification, block-local raw codec, requested-wind loading, durable state reuse, or liveness specialization. Do not revive failed reassociation/horizon/moment designs unchanged. Recompute combined work rather than multiplying overlapping speedups.

## Phase E: freeze and final-scale observation

Require source/wheel/environment/profile freeze, accepted family reviews, passing actual small TIFF/state/metadata checks, complete guards/fallback tests and a frozen final protocol before L4. The primary cache regime, outputs, physical resolution, tile extent/overlap and checkpoint policy are unchanged. Default is the complete first-use local pipeline unless a prior authorized target specifies otherwise.

Final owner runs the actual 24-tile batch once, including required geometry, JIT, application I/O and artifact publication. No separate mandatory 1024 warmup. Reuse matching numerical references. New full baseline default zero; one justified missing-reference capture is permitted at the final stage, or label large numerical parity unverified. First large tile is part of the final campaign, not an extra admission round.

Abort/record according to the frozen deadline/resource rule. A failed/censored attempt remains evidence. Fix via a small reproducer; one causally justified final retry is preauthorized after refreeze. Further full campaigns need a new decision, not infinite retries hidden behind unlimited tokens. One pass is `target_demonstrated_once`, not reliability, a general speedup distribution or full release qualification.

## Phase F: branch handover

Prepare the immutable merge-review packet: base/tip/tree/wheel, exact model routes actually used, reviewed changes, test evidence executed/reused/deferred/failed, small timings, final observation or blocker, resource use, limitations and reproducible commands. No main merge, push, PR, auto-merge, release or hosted benchmark unless separately authorized.

If the absolute target remains unmet, deliver the best verified branch and a compact measured residual model. Keep remaining work explicit. Do not stop at a stub/prototype/import pass; do not prolong work merely to implement every catalog idea once the scoped target is satisfied.
