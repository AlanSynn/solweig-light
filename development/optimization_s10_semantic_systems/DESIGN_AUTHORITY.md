# S10 design authority

## Objective
Deliver the smallest set of measured semantic and system improvements that materially reduces installed, end-to-end SOLWEIG-light service time and increases throughput under an unchanged resource budget. Cover ordinary no-environment-variable use and landcover-daylight fallback explicitly. Preserve API, CLI, physical model, numerical profile, outputs, state and durability. Native or GPU use is a means, never an acceptance requirement.

This is a NEW scoped campaign over current main. It does not reopen N8/N9 gates, erase failures, revive the native-default objective, or authorize edits to frozen historical records. New exact CPU changes are authorized; optional heterogeneous feasibility is authorized only through the selection rules below. Real-algebra-only, reduced-precision and operational-contract changes remain design-only unless the user separately authorizes them.

## Fixed decisions
1. Target the representation/profile coverage gap before another reducer backend contest.
2. Keep scalar S, singleton-array U, and genuinely varying field F profiles distinct. Rank and dtype provenance are part of the operation graph.
3. Never route `.item()` output through the old scalar kernel as a shortcut. First preserve coefficient computation, then compile a verified typed DAG.
4. Preserve patch order and per-output recurrence; parallelize independent receivers and jobs.
5. Default arithmetic has no reassociation, implicit precision reduction, unapproved contraction, approximate reciprocal or replacement transcendental profile.
6. A large task list is a SEARCH SPACE, not an instruction to implement every candidate.
7. Reuse accepted streaming, common geometry recipes, sparse wall filters and persistent pools. Extend only measured missing parts.
8. Compare A=current accepted default, B=same optimization in existing backend, C=alternative backend with the same producer/layout. Keep upstream CPU U and historical main H separate.
9. Count producer, admission, conversion, initialization, allocation, synchronization, output and checkpoint work. Leaf speed alone cannot qualify.
10. Treat memory ownership and phase overlap as proof obligations. Compact persistent storage does not eliminate decoded workspace or mmap resident pages.
11. Keep source-check and durability obligations. Never replace content validation with mtime/size or disable checkpoints to pass performance.
12. Keep ordinary users' dependencies and calls unchanged. No new required env, compiler, GPU, network service or backend choice. Optional accelerators import lazily and fall back before launch when unsupported.
13. Resource defaults remain as in main unless a separate preregistered policy explicitly permits an internal change within the same granted budget. Do not silently spend four cores to win a one-core default cell.
14. A failed optimization is reverted from the product while evidence is retained. No more native leaf benchmarking unless broader measured stage coverage and a new causal design repay it.
15. Work on the NEW local integration branch `perf/s10-semantic-systems` created at current main (b3e5ca59 or rechecked HEAD). Deleted campaign branches are never merged or recreated. Main itself remains unchanged. See BRANCH_AND_CI.md.
16. General failures are debugged locally. New science, weaker numerical/durability contracts, secrets, purchases, publication or unsafe user-work conflicts are escalation boundaries.
17. No repeated manager polling, transcript replay or mandatory Astra callback. GLM/Opus implementers and independent reviewers finish the work.
18. Final target runs are late and bounded. Missing target data/hardware is unavailable, never passed.
19. Every activated default path must show actual route coverage on its predeclared domain. A fallback result cannot certify the optimized implementation.
20. Completion is a finite product decision plus a merge manifest, not a list of future flip conditions.

## Delegated decisions
Workers may choose local helper names, exact typed signatures, scratch allocation details, bounded block choices, legal loop schedules and proof-preserving implementations. Reviewer may reject a proposed proof, narrow only a predeclared eligibility predicate transparently, or choose the retained path. Do not hide newly losing cells, retroactively redefine target coverage, or revise post-result thresholds.

## Three semantic levels
E: execution/observational equivalence within frozen profile, including dtype and output/state bits.
G: guarded E; unsupported or unusual inputs use the original verified route before launch.
R: exact in real arithmetic but changes floating-point evaluation or operational behavior; specification only, no default implementation authorization.
