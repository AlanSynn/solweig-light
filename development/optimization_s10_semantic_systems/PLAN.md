# S10 execution plan: broad analysis, narrow implementation, finite closure

## Goal and baseline
Optimize the installed current-main product, not a retired scalar kernel or an old branch. Preserve exact model/DX and finish with a reviewed merge candidate. Main reviewed at b3e5ca59 (v5-N9 closed, evidence archived to Dropbox); the old perf/native-optimization branch is deleted and is never restored. Refresh/read local state before changes. Historical N9 is CLOSED and stays closed; S10 is a new campaign on new representation/system opportunities.

## Phase 0: reconcile, inventory, freeze (S10-00..03)
Create the new local integration branch `perf/s10-semantic-systems` at current main per BRANCH_AND_CI.md; preserve unrelated user work. Capture immutable A source/environment/API manifest. Run read-only source audit and inspect selected functions' complete dependencies. Use existing evidence where unchanged; do not run full historical suites to rediscover known failures.

Build one real route census on small landcover and no-landcover scenes. Cover day/night, actual singleton/scalar types, active patches, low-level fallback reasons, leaf and effective thread counts, geometry production count, raw-mode share, writer/checkpoint time and measured byte traversals. No cProfile-derived runtime percentage is accepted as unprofiled timing. Require no-profile perf_counter timing separately. Imported user benchmark logs remain unverified until source/fixture/power/timer boundaries are checked.

Freeze baseline noise and the small held-out cells BEFORE candidate performance. Select a finite implementation portfolio. T01 is first if U fallback is present. G01 and R03 are initial parallel candidates only if their stage costs justify implementation. System S07/S09/S03 require measured I/O/memory coverage. Other candidates receive decide/defer/reject rationale.

## Phase 1: independent high-value implementations (S10-10..15)
Numerical worker: U typed plan, coefficient preparation, exact kernel and route coverage. Do not begin native re-porting.
GVF worker: serial prepared path with guard and water/alias preservation.
Diffuse worker: ordered aniLum block kernel, not speculative whole-pipeline fusion.
Systems worker: ONE selected I/O or memory improvement from measured baseline, with its complete integrity/failure contract.
Fixture/reviewer workers can prepare negative tests and immutable reference traces independently. Shared driver edits land only through integrator patches.

At most two closely related tuning variants per numerical design. An experiment may have broad reasoning, but not unlimited tuning runs. A candidate with low fraction or failed parity is rejected early; do not expand scope to justify sunk effort.

## Phase 2: integrate and re-profile (S10-20..25)
Integrate independent passing patches on the same branch, with author != reviewer. Run dependency-affected L1/L2 tests and current installed defaults. Re-measure residual stage costs. T03 tables/R01 predicate cache/T06 classifier sharing enter only after T01's real coverage and new profile are established. Do not multiply estimates for overlapping erased work.

Conditional geometry/system residual work has ONE further selection round. GPU/native feasibility enters only with a predeclared large region, actual hardware, safe dtype support and modeled break-even. At most one backend candidate is implemented; others remain documented. Accelerator results never substitute for core default CPU/DX success.

## Phase 3: held-out small campaign and default selection
Freeze final source, wheel, environment, workload, runtime masks and measurement boundaries. Use three alternating paired observations per selected small held-out cell. Keep full timelines at 24/48 steps. Do not choose per-stage minima or subtract standalone overheads from E2E. Report all failed/noisy/censored runs and causes. One controlled remeasurement after an external problem may be permitted by a predeclared rule; no repeated attempts until a favorable result appears.

Default optimization must improve actual no-env use, not require a magic env/CLI. Tuned configurations are reported separately. Static predeclared fallback guards may keep unsupported shapes/profile on A, but never hide new losing target cases or claim full coverage with fallback.

## Phase 4: final validation and closure
Only the selected immutable candidate is eligible for one large run on the actual manifest (24 distinct logical spatial tiles of target size, full timestep count, original resolution/patches/outputs). One small-reproduced causal fix allows at most one additional large candidate run. No large tuning matrix. If actual data/reference/hardware are missing, record actual_target_unverified. Do not fabricate a 24-tile corpus from two motif scenes.

If original-upstream target parity is required and no reusable independent reference exists, allow at most one explicitly registered baseline target execution at final qualification, or declare that gate unavailable. Do not generate upstream goldens from candidate code.

Freeze final active defaults, installed wheel/source DX, relevant API and numerical tests, process-tree memory and local PR-required checks. Produce FINAL_DECISION.json and MERGE_MANIFEST.json against the ACTUAL current-main SHA. Do not push/PR/merge/release. Remove unneeded experimental runtime scaffolding from installed closure; preserve research evidence outside it.

Terminal states: qualified_exact_cpu; qualified_heterogeneous_optional; retained_main_no_material_gain; blocked_no_safe_merge. Goal achievement, campaign closure, native/GPU qualification, actual-target status and merge readiness are separate fields. This campaign terminates after these rounds; no open-ended follow-up obligation.
