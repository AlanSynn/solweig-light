# D02: Exact partial evaluation and classification reuse

Candidates T03/T05/T06/T07/T09/T10. Follow D01 typed-origin rules. Sources S03/S06/S07/S27/S28.

## Contribution tables
Suppose the original contribution is `Eval_tau(surface, sun, solid[p], cosine[p], building)`, with two Boolean arrays. For a spatially uniform source and the same typed profile, precompute Q[p,s,b] for four states using the ORIGINAL array operations on representative Boolean arrays. Store Q in the original contribution dtype. A float64 contribution followed by float64 addition and float32 accumulator storage MUST stay float64 until that addition.

For receiver x:

    for p in ORIGINAL_PATCH_ORDER:
        acc[x] = original_typed_add_and_store(acc[x], Q[p, sun[x,p], building[x,p]])

Do not pre-add sun and shade tables if the original adds them separately. Do not algebraically factor solid*cosine if the original rounds after each multiply. Do not remove masked multiplication from nonfinite-domain arithmetic. Independent accumulator families remain separate.

The expression-evaluation count changes NP -> C*P, C often 2 or 4; NP lookup/add work remains. C*P small float64 tables can be cache-resident (4*153*8=4896 bytes per table), but too many tables increase register/cache pressure. Measure two limited variants, not an exhaustive layout search.

## Domain and error admission
Evaluating all states can trigger overflow/warnings in a state that no actual receiver uses. Prove all evaluated states safe, restrict tables to actually used states without changing original error order, or fall back. Nonfinite, aliasing, shape and math-profile outliers are explicit retained-path cases. A table generated by the candidate is NOT an oracle; compare every contribution and prefix against the original expression.

## Exact classification reuse
The existing classification tables and R04/G06 work are baseline. New work must concern inputs or repeated calls they do not already eliminate.

1. Reuse exact tan32(asvf), but bind to source bits, math profile, layout-tail behavior and geometry lifetime.
2. Enumerate exact unique ASVF states U. Bit identity, not rounded bins. Include signed zeros/profile and all other classifier inputs.
3. Classify U values across P patches and scatter N output labels. Remaining NP stores may dominate. Measure unique ratio and total grouping+scatter cost first.
4. Share shortwave/longwave classifications only after exact-key census. Patch tables, azimuth conventions, scalar dtypes, active solar masks and trig implementations must match. A superset evaluation can change errors, so prove it safe.
5. Avoid persistent NT*P masks. Prefer sharing a bounded block or one invocation's immutable view.

## Certified threshold classification (conditional research inside exact policy)
A comparison `D(h,c) < beta` may avoid expensive evaluation if an interval [Dlo,Dhi] rigorously encloses the IMPLEMENTED math routine under this profile. Dhi < beta or Dlo > beta certifies a result; equality/uncertainty uses original evaluation. Real atan monotonicity alone is not a certificate for SLEEF/NumPy/target compiler behavior. This is not in the initial implementation wave.

## Uniform and low-entropy fields
Use a tagged value only when construction proves uniformity or when a one-time exact check amortizes. Preserve repeated-zero arithmetic and source rank semantics. Never rewrite Tgmaps as clean class-ID lookup without testing its current successive value replacement behavior; a value written for one class may equal a later ID. This is an inherited implementation quirk, not permission to correct the model during optimization.

## Measurements
Record table bytes and setup, evaluations avoided, lookups, cache/profile hits, classification calls, wrapper time and peak workspace. Profile coverage comes from real scalar and landcover scenes. Reject when table/scatter cost erases savings. T01 and T03 overlap the same former Python path, so do not multiply their independently estimated speedups.
