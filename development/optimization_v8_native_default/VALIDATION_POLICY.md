# Lean validation with stronger default-deployment gates

## Tiers

L0: typed-node arithmetic, state projection, layout permutation, bounds/alias/registry/manifest/branch guards.
L1: actual unchanged kernel versus candidate, mostly small arrays with real captured scalar profiles, B=0/1/tails and long P guard cases.
L2: genuine 64/128-square TIFF-to-TIFF with all 24/48 records, required intermediate fields and every carried state. No numerical mocks. Service mocks for optional acquisition must be labelled.
L3: 128/256-square held-out small multi-tile pipeline, fixed resource shortlist, installed no-env default and deliberate baseline controls.
L4: only final fixed source/artifact/configuration on one scale/actual target campaign. See BENCHMARK_PROTOCOL for run budget.

Execute tests after a coherent change, not every file edit. Relevant family tests after family changes, affected integration tests after shared changes, installed-wheel tests after packaging/loader changes. Do not rerun all historical P0-P8 suites by rote. Reuse valid evidence only for unchanged dependency closure, tests, fixtures, profile, compiler, harness and execution policy.

## Required comparisons

Compare masks/metadata first, exact finite bits and signed zero where required, NaN/Inf masks and raw codec payload bits separately. Branch-to-candidate exactness is distinct from original upstream budgets and scientific exceptions. Main DX snapshots are not a numerical oracle. Full diagnostic functions remain available even when private demand omits fields.

Check alias mutation, shape-sensitive math, output ownership, first-step behavior, input-change detection, corrupted/missing caches, durable restart, failure cancellation and bounded resources. Unsupported candidates decline before launch. No unqualified numerical values are silently promoted to valid output by falling back after an admitted failure.

## Default test boundary

API/CLI calls without backend flags and without changed public defaults must run through the actual installed package. Native wheel host must execute meaningful native work; pure-source/no-native fallback must run correctly and is labelled fallback. These two passing tests are not interchangeable. Refuse hidden first-run compiler/subprocess/network use by the native default path.

Match existing error behavior in general/public inputs; use narrower validated private routes where necessary. Do not spend indefinite effort reproducing undefined crashes; specify admitted behavior and preserve trusted fallback outside it. Correct contract bugs that would permit unsafe memory writes rather than relying on old bugs.

## Reviews and budget

Every promoted numerical/lifecycle/packaging change has an independent immutable-diff review. Reviewers inspect existing evidence before rerunning tests; no automatic full duplication. Additional proof/counterexample agents are unlimited in number but local tests/builds need reservations. One performance owner at a time.

Failures remain in records. Missing hardware/corpus/reference is unavailable, not skipped-as-passed. No gate/tolerance relaxation after new failures. Keep model deviations and residual risks current. Pre-existing memory-sensitive fixture behavior is dispositioned explicitly; pin a fair reproducible resource envelope in a test rather than suppress it.

Packet self-tests validate only these helper tools and document consistency. They do not assert SOLWEIG, native, wheel, UI/API or physical correctness.
