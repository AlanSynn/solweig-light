# Completion-driven delegation with a small-validation ceiling

## Routing and scope

Astra handles the initial contract, portfolio choice, genuine cross-family proof decisions and final handover. Delegate bounded numerical implementation, differential debugging and test repairs to Luna Max if actually available. Resolve supported model/effort once from the executing environment and record the actual choice. Use lower effort for manifests and mechanical work. Do not claim specific wire model IDs, default routing or subagent support without checking that environment. If delegation is unavailable, run the same packets serially and record that limitation.

Start with at most four sessions: rays, radiation, GVF, runtime/evidence. Review and integration reuse released slots. Do not recursively spawn subagents. One owner per production scope; one integrator alone edits shared engine/pipeline/API dispatch and central status. Read-only proof review may overlap an implementation, but no second writer competes on the same file.

## Branch model

Integrator: `perf/lean-cpu-v4`, isolated local worktree. Family worktrees use distinct branches from one recorded integration tip. Family completion contains an immutable commit/patch and any shared-file integration recipe. Integrator imports accepted changes to the optimization branch only. No worker pushes, opens a PR, touches main or enables auto-merge. See `BRANCH_AND_CI.md`.

## Validation delegation

Each family packet states `maximum_tier: L2`, owned fixture/reference paths, permitted commands, dependency evidence keys and watchdog caps. Workers can autonomously run and repair tiny/actual-kernel/small-chronology checks. They cannot enlarge a test to 1024, rerun every upstream fixture, allocate the whole machine or start a full-batch benchmark.

L3 is a shared lab service for at most two finalists, not four independent worker benchmark suites. L4 is a single final-scale campaign after combined source/wheel freeze. No worker bypasses this via an internal subprocess, a differently named harness or hosted CI. Size is determined by actual logical input dimensions and workload, not just CLI option spelling.

Reviewers read source-bound evidence and evaluate the proof. Rerun only if an identified hole, inconsistency or dependency change requires it. The integrator tests new cross-family interactions and builds a stable installed wheel once. Do not rerun identical mathematics or rebuild identical environments for reassurance.

## No progress supervision loop

Use real completion events or supported blocking waits. A worker implements, tests, inspects, repairs, and emits one terminal result or genuine blocker. No repeated "are you finished?", transcript replay, duplicate lead implementation, human approval per local edit, or background status daemon. Process resource monitoring is allowed and remains distinct from LLM supervision.

If a test budget is exceeded, the worker retains the timeout and seeks a smaller valid reproducer or another strategy within scope. It does not loosen tolerances, delete tests, hide a failure with unconditional skips or start unbounded retries. A genuine unresolvable boundary is returned as a compact decision packet. Work on other independent tasks continues.

## Context and reporting

Task packet target: <=1200 words; terminal summary: <=350 words. Include exact base, owned files, objective, relevant dossier/proof sections, admitted domain/fallback, commands, fixtures, validation tier and stop condition. Full logs, traces and numerical diffs stay in files. Workers do not receive the entire strategy catalog or chat history.

Record executed and reused checks separately; reused checks point to the original evidence and matching dependency key. Record test/JIT/setup time, model/effort and available charged usage. Unavailable usage is unknown. No new claim of token savings without measurements.

One compact lead ledger tracks task, source, owner, status, evidence and next dependency. Family workers write separate result files; integrator alone updates central status. No numerical test is triggered by a status-only edit.

## Quiet benchmark host

Agent-session parallelism and SOLWEIG tile-worker parallelism are separate. One lab owner holds the performance lease. During small timing comparisons and the final target run, other sessions must not run local tests, compilers, builds, compression or profilers in the measured resource envelope. Paired trial order is fixed before measurements. Keep contaminated/censored outcomes and their reason; do not cherry-pick quiet runs after seeing speed.

Astra performs the final review from immutable evidence once. Deliver the best verified optimization branch, exact scale of completed checks, final observation or blocker, deferred release work and merge instructions. Stop before push/PR/main merge unless separately requested.
