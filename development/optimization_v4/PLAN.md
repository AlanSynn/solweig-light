## 3. Validation ladder, not a large benchmark loop

`VALIDATION_POLICY.md` and `validation_policy.json` are the operational authority.

| Tier | Default scope | Trigger |
|---|---|---|
| L0 | Typed arithmetic, state machines, guards, tiny arrays | Changed mathematical logic or a new counterexample |
| L1 | Actual kernel differential, usually 16-128 pixels per side | A coherent family patch |
| L2 | Real 64-128-square TIFF pipeline, complete 24/48-step small chronology | Family integration; day/night, state, I/O and restart dependencies |
| L3 | 128/256-square paired timings and a small multi-tile batch | At most two shortlisted variants; one shared evidence owner |
| L4 | Actual 24 x 1024-square batch, 24 steps, 153 patches | Once for the frozen combined final candidate, not for each strategy |

Small fixtures are separate test cases, not cropped substitutes for the final scene. Preserve physical units and original support for each fixture. Do not shorten the final model. Keep threshold, first-step, border, raw/nonfinite, alias, water, positive-bush, non-square and long-ray adversarial cases in L0-L2. Use supported fixture sizes; for a structural constraint, one specifically justified fixture may use up to 256 per side. A 512-square probe is exceptional, reasoned and cost-bounded; no routine 1024-scale run before L4.

Retain full chronology on a small spatial grid. Short 2-6-step kernel tests are useful for focused branches, but never replace small 24/48-step carried-state tests. At least one real CPU-only TIFF-to-TIFF test uses actual numerical kernels without mocks or unconditional skips. Large tests are explicit manual selections, not silently skipped members of the required small selection.

Run relevant tests after a coherent behavioral patch, not every keystroke, comment edit, prompt update, status write or local commit. Rebuild an installed wheel once for a stable integration candidate, or earlier only if packaging/import changes need it. Cache evidence by the complete dependency identity described in the validation policy. Unknown dependencies require conservative reruns.

## 4. Evidence-selected implementation and review

Collect stage/copy/decode/ray/cardinality/resource counters on L1-L3 only. Timing sessions are exclusive; coding agents must not launch competing builds/tests on the same host. Warm compatible JIT once outside repeated kernel timings; first-use is measured separately, never hidden. Do not collect every candidate's complete execution trace on every repetition.

First-wave owners: ray absorption/suffix bounds; ordered radiation and exact partial evaluation; GVF preparation/fusion; memory admission/persistent workers. Assign at most four worker sessions and one writer per scope. Each worker has one small packet, relevant dossier and tests, and the L0-L2 ceiling. Only the evidence owner can run L3. Only that owner after final freeze can run L4. No recursive delegation or worker-requested full-batch repeats.

Each numerical patch includes its fast-domain proof, negative controls and unchanged fallback. Use actual baseline kernels, not only rewritten toy recurrences. A distinct reviewer reads diff/proof/results at completion; it need not reexecute unchanged evidence. The integrator alone edits shared engine/pipeline/API dispatch and integrates accepted worker commits into the optimization branch, never main.

Continue implementation, test inspection and repair autonomously. Completion events or supported blocking waits replace LLM progress polling. Timeouts are retained failures/censored outcomes; they are not passing tests. Fix the cause or choose another strategy rather than expanding runtimes blindly. No scientific correction, tolerance relaxation or unsupported approximate transformation is implied by this operating policy.

## 5. Small-scale portfolio selection and scaling risks

Use only a compact measured tuning set, normally 128 and 256 squares and no more than four predeclared worker/thread/block tuples under the same resource budget. Start with one paired AB/BA diagnostic comparison; no confidence or general speed claim follows from it. If two finalists are too close for a decision, use at most two additional pairs on that same small protocol. Keep every outcome. Select based on actual time and memory, not a desired speedup.

Before a winner is frozen, record predictions and uncertainty for the large run. Small-scale timings cannot establish 1024 throughput: cache residency, ray length, JIT specialization, compression, memory bandwidth, and allocator thresholds can change with size. Counter-based work models and dependency proofs supplement small tests; they do not certify large throughput. Never resize a real context-sensitive tile merely to extrapolate it as identical work.

## 6. Freeze and one final-scale campaign

After L0-L3, independent reviews, and one installed small pipeline check, freeze source tree, wheel, math profile, environment, actual input manifests, CPU/RAM/storage envelope, outputs, checkpoint frequency and one primary cache regime. Default primary remains first-use complete local pipeline unless an existing authorized target explicitly defines another regime. Small-scale tests cover cold/warm variants; do not multiply L4 across those regimes.

The target remains 24 actual 1024x1024 spatial tiles, 24 chronological steps each, 153 sky patches, <=1800 seconds through required artifact publication. Aim for 1200-1380 seconds analytically, but no modeled pass counts as measured. The final first tile doubles as the large preflight inside the same timed batch; do not run a separate 1024 warmup and hide it from a first-use result.

Default: one candidate full batch. A full baseline rerun is not required for an absolute <=1800-second observation. Reuse an exactly matching retained reference when available. If a missing final numerical reference must be generated, the final protocol may admit at most one frozen-baseline batch, with the reason recorded before candidate evaluation; no default/tuned/original baseline sweep. Otherwise label large numerical parity unverified and limit the claim. A new candidate is never that baseline.

Verify large output schemas/masks and numerical values against valid matching references where available. All-timestep state and detailed radiation evidence come from the small full-chronology traces; do not imply large per-step traces were collected if they were not. Include runtime-required content checks, checkpoints and exports inside measured application time; report external post-run comparison time separately as validation cost.

Do not automatically run five pairs, a full 1024 tuning grid, 2048/3600 scenes, every optional service, all OS/Python combinations, or the entire historical release matrix. Those remain separately budgeted release tasks. Existing mandatory branch-protection checks still apply when a merge is later requested.

If L4 fails, preserve artifacts and minimize the failure to L0-L2 where possible. Permit one additional candidate full-batch attempt only after a causal fix passes the affected small tests and new source identities are frozen. Never rerun unchanged code to fish for a faster sample. Further L4 campaigns require a separate budget; finish with the best verified branch and explicit unmet gates rather than an endless expensive loop.
