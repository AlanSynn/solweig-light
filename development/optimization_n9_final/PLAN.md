# Final campaign, not another open-ended optimization program

## Terminal product choices

- `closed_native_qualified`: all inherited native gates pass on named platform/configuration; compiler-free installed no-env execution uses native where eligible; fallback stays intact. Final source is merge-ready if release safety passes.
- `closed_cpu_only`: native loses or cannot be qualified within this campaign. Keep demonstrably useful Numba/CPU changes and accepted prior CPU improvements. Remove dormant N8 shipping complexity. Native work is closed for this release, not left as a requested next-session task.
- `blocked_no_safe_merge`: final tree cannot meet required safety/numerical/DX or merge-conflict obligations. Explicitly recommend NOT merging. Do not manufacture merge readiness because the project should end.

Packet completion, native achievement, merge readiness, original-upstream speed and 24-real-tile target are separate fields.

## Sequence

### F0: one inventory and protocol freeze

Read N8 selection, tier-B record, actual source and current main. Record which improvements are ACTIVE, which are only retained, and default imports. Include packaging configuration and CI deltas in the main diff. Reuse valid references without regenerating upstream. Fix the zero block-size harness acceptance and evidence labels as a small audit delta. Freeze actual timer boundaries and inherited gates before any new target-host variant result. The supplied independent Linux microexperiment belongs to development priors, not held-out evidence.

### F1: two implementation scopes, one release scope

- Producer owner: literal-mode decoder plus direct mask output, same improvement to B and A-compatible layout where applicable. Only two closely related decoder variants allowed on tuning data (literal mode; optional byte-group load). No new codec format.
- Stream owner: native prepared plan and bounded slot lifetime, existing kernel and region scheduler. Remove redundant public-adapter work from private proven buffers, not from unknown callers.
- Release owner: main comparison inventory, active CPU-only fallback tree, package exclusions, artifact/provenance and exact installed tests. This work proceeds irrespective of native outcome.

Interface freeze is a small agreed input/ownership table; do not construct a framework hierarchy. All existing aliases, errors, f32/f64 nodes and source identities stay binding.

### F2: combine and review once

Complete tiny state/bit tests, actual kernel differential, scratch reuse and read-only/exception tests. One independent reviewer examines the combined changes and evidence. Apply one cohesive correction set. A critical bug is fixed or its patch is excluded; no performance optimization is protected from reversion.

### F3: one actual producer-to-output selection

Use continuous wrapper timing, not sum-of-minima. Retain same-resource A8/B/C, B=128 and 1024, three visibility mixes, actual f64 and f32 guard, H=1/4 where admissible. Run the frozen small real chronology and compact multi-tile cells. Stop C if it misses gates or clearly cannot materially affect the full pipeline. Do not expand to larger blocks/frameworks to rescue a loss. Select one final implementation.

### F4: production and packaging disposition

If C qualifies provisionally, finish the installed-artifact boundary and no-env pipeline. A repo-only C or a pure fallback wheel is not native qualification. If it fails installation/region/pipeline gates, select CPU-only immediately. In CPU-only closure, remove unselected auto-selection and runtime artifact machinery from the installed path via a forward commit, preserving history and explicit expert compatibility.

### F5: final confirmation and merge manifest

Build from the selected immutable source and verify installed imports/API/CLI, exact small chronology and fallback. Compare final default with pinned main on the compact frozen user workload. If a real 24-tile corpus with qualified reference coverage exists, one final target campaign is optional within the predeclared budget. Otherwise use at most one declared synthetic/available large confirmation or none if existing evidence and small gates suffice for a CPU-only merge; neither substitutes for the actual target. No mandatory large runs on losing candidates.

Produce FINAL_SELECTION.json and MERGE_MANIFEST.json. Rehearse a merge against pinned main in an isolated detached worktree. Compare its tree/source digest to the qualified final artifact. If main moved, recompute conflicts and affected small tests before declaring ready. Leave main unchanged.

## Experiment limit

This is an engineering design limit, not an elapsed-time promise. One integrated candidate family, at most two narrow producer variants on tuning inputs, one causal correction set before the final comparison, one final comparison sequence. At most one environment-interrupted sequence may restart after a recorded cause is removed. A valid performance failure is terminal. No open-ended wait-for-loadavg loop, no p95 claims from three observations, no automatic next packet.

## Scope deliberately excluded

New GPU/framework backend, predicate codec redesign, alternative thermal comfort model, non-exact transcendental profile, ray physics changes, unbounded autotuning, broad OS/release matrix, library/plugin ecosystem setup, repeated policy-document rewrites. These may exist in historical research documents but are not dependency-ready tasks in this campaign.
