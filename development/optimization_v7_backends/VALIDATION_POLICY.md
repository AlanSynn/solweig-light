# Lean validation and immutable evidence

## Evidence classes

Distinguish untouched original upstream, explicitly patched upstream, accepted current Numba snapshot A, equivalent-layout Numba B, foreign candidate C, abstract synthetic checks, source inspection, hypothetical models and actual measurements. No candidate-generated golden or tolerance relaxation. Current scientific exceptions stay failed/dispositioned with their original scope. A new backend requires exact current-profile comparison while preserving existing upstream budgets; those old budgets are not permission to make backend results merely close.

## Tiers

| Tier | Scope | Trigger |
|---|---|---|
| L0 | tiny float/bit/guard/capability/tail/lifetime tests | a coherent arithmetic or adapter change |
| L1 | real baseline and candidate kernel, normally 16-128² or smaller explicit B,P | a completed kernel change |
| L2 | real 64/128² TIFF-to-TIFF, full 24/48-step chronology, target 153 patches | family/dispatcher integration |
| L3 | 128/256² small distinct-tile batch, compact thread/block shortlist | serious candidate selection |
| L4 | actual 24 target spatial tiles at 1024², each 24 records | only final immutable winner |

Do not run 1024 after every commit, per backend, or for routine warmup. A 512 probe needs a specific scale-only issue smaller fixtures cannot answer. Reducing spatial size for development never authorizes reducing the final model resolution, patches, chronology or ray support.

Keep fallback, raw visibility, warnings/error order, NaN/Inf/signed zero, dtype and mutation tests. First compare shapes/dtypes/nonfinite/sentinel masks, then finite exact bits, then all carried state at every small timestep. Compare each of the seven first-island outputs; include accumulated nodes at checkpoints in diagnostic mode when needed. Fast-domain guards must be exercised on their boundary and negative controls must prove the general path is still used correctly.

Native memory safety tests cover masked tails, alignment, strides, read-only arrays, input canaries and aliasing. Trace/IR tests verify no new contraction or patch reduction; actual numeric tests remain necessary. Do not reinterpret disabling FastMath as a proof.

## Reuse, not repetition

Reuse executed evidence if the full relevant source/dependency/profile/compiler/test/fixture/configuration closure is identical. Documentation-only edits need not trigger numerics; changed common helpers do. Reviewers inspect the actual evidence before rerunning. Reproduce only ambiguous or high-risk cases. Missing output logs, source provenance or interpreter identity makes the associated claim unverified, not assumed passed.

Do not run the entire historical suite, reference generation or installed-wheel matrix after each edit. Run affected cases, then one meaningful small integration before promotion. Backend absence is `unavailable`, not passed via skip. Core-only required TIFF test has no unconditional skip or numerical mock. Optional network service mocks remain labeled.

## Final campaign policy

Final candidate allowance: one campaign. New full-size baseline default: zero. If missing references prevent the intended claim, allow one justified final-phase reference capture or keep that scope unverified. There is no automatic 24-tile reference generation for every framework. Existing two-scene outputs do not cover 22 other tiles.

Freeze target manifest, source/build/profile, requested outputs, checkpoint policy, true logical extents, input resolution, cache regime, CPU/RAM/storage, backend, thread pools and clock boundaries. Timeout/OOM/cancelled trials are retained. One corrective retry is allowed only after a causal fix, small reproducer/regression and a new freeze. Extra attempts are not automatic because inference tokens are unlimited.

If actual target data is absent, finish the small comparison and integration rather than inventing a substitute target. Repeated synthetic scenes may be a labeled load test, not 24 distinct target tiles. A single success supports one-run observation only, not p95/reliability or complete P7/P8 release qualification.

## Names of outcomes

- `comparison_complete_no_winner`: available tracks were actually investigated, with rejection evidence.
- `numba_layout_improvement_integrated`: B improved the measured scope without a foreign runtime.
- `optional_cpu_backend_integrated_local`: exact and improved on the named local scope; portability listed separately.
- `actual_target_unverified`: missing data/reference/hardware or no qualifying final run.
- `actual_24_tile_target_demonstrated_once`: all frozen target jobs completed within time/resources with the stated required numeric coverage.

One status does not imply another. A routine backend bug is repaired locally; scientific policy changes are not silently substituted. No automatic CI broadening or push accompanies these outcomes.
