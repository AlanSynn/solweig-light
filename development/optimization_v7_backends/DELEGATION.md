# Delegation: GLM coordinator, useful independent Opus/GLM work

No Astra/Codex calls are required. High-level constraints are already in the packet. Actual Opus is preferred for demanding float/ABI proof, difficult native implementation, and independent review when available; GLM-5.3 handles orchestration and bounded implementation. Actual route/effort is recorded, never inferred from the display name. Do not request credentials or install a gateway.

There is no artificial total inference token/agent-count cap. Parallelize independent thought, fixture construction, backend alternatives and review. Do not confuse this with unbounded CPU/RAM/build jobs. A compiler or pytest job consumes local resources just like a model worker's command. The performance owner holds an exclusive host lease. Read-only remote inference can proceed during timing only without local builds/tests/large scans/downloads on the measured host.

## Roles

- Coordinator: initial inventory, routing, task packets, dependency-ready scheduling, exceptional decisions and final disposition. It does not reimplement every worker's code.
- Contract/fixture owner: actual reference captures, typed-node ledger, immutable corpus and A/B controls.
- Native SIMD worker: ISPC **or** Highway first; not two complete production native runtimes without evidence.
- Dr.Jit worker: LLVM-only, typed symbolic loops and synchronized adapters.
- OpenCL worker: real CPU device, runtime/capability/thread controls and strict arithmetic.
- Conditional pointwise worker: MLX CPU or Halide only after a named measured residual justifies it.
- Reviewer: different agent from author, immutable patch, proof+diff+negative tests. Can reproduce the smallest disputed case; no habitual full reruns.
- Integrator: sole owner of branch commits, shared wrappers/identities/packaging and task state.
- Performance owner: independent-process fair A/B/C trials and final campaign.

## Task packet

Include immutable base SHA; exact owned paths; input/output contract; one dossier; required captures; concrete deliverable; admission/fallback domain; permitted test tier; host resource reservation; terminal paths. Worker context contains only relevant documents and code, not every past handoff and raw transcript. Tokens are available, but duplicating unrelated context is still slower.

Family code goes into owned experimental modules until promotion. Same-file alternatives use detached worktrees at the same frozen base. If helpers need changing, send an interface proposal to the integrator rather than racing to edit shared files. Only an independently reviewed immutable patch is integrated. Tests run against the patch's actual dependency state, not a mutable shared tree.

## Completion, not supervision loops

Worker executes implement -> run -> inspect -> repair -> focused re-test on its own. Report only terminal completion, rejection or genuine blocker, plus files, commands, evidence scope, raw timings, remaining problems. Use actual runtime completion events or blocking waits; do not send repeated status checks, poll model sessions, or replay full transcripts. Low-level process monitoring for timeout/OOM is required safety, not prohibited manager polling.

If the environment lacks multi-agent spawning, run independent sessions or sequential roles with honest provenance. Do not label author self-review independent. Resume another dependency-ready task when one backend is unavailable. Infrastructure setup must not consume the optimization campaign; local user-space install is allowed, privileged/global changes are not.

Completion-triggered reviewer and integrator jobs can run repeatedly per immutable candidate. Their DAG rows are services, not a single global review that blesses every later edit. Any numerical change after a review invalidates that review for its affected scope.
