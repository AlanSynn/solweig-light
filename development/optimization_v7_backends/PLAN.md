# Backend continuation plan

## Mission

Deliver the smallest optional CPU backend portfolio that demonstrably improves SOLWEIG-light throughput over the best same-resource accepted/Numba-layout baseline. Preserve exact current-profile behavior and a portable Numba core. The long-range workload remains 24 **spatial** 1024² logical tiles, 24 chronological records per tile, 153 patches, unchanged outputs/checkpoint policy, <=1800 seconds on a named resource envelope. This goal is not guaranteed by a kernel result.

The previous survey is design evidence, not a executed framework comparison. `SOURCE_STATUS.json` records source observations. At kickoff record actual local HEAD and protect dirty files. Do not reset a newer checkout or infer source identity from a branch name.

## B7-00 to B7-04: one inventory, one typed boundary

Read current applicable repository instructions, this plan and task DAG once. Verify the current reducer is reachable from the real TIFF path, including private demand, input dtype and feature flags. Preserve all accepted v6 work. Fix measurement interpretation, not old reports: historical 598.9s is two scenes, current v6 timings are dev-tier, and RuntimeOptions alone is not effective native-thread control.

Locate the target data and current reference fixtures; do not demand a new dataset for small implementation. If the actual 24-tile corpus is absent, make progress on labeled small fixtures and leave the final target blocked. Do not replicate two scenes and call that the target.

Capture actual function arguments from untouched reference execution without replacing the function. Record shapes, strides, read-only status, dtype/scalar form, byte hashes, math/profile/source/compiler identity and emitted seven columns. Copy captures outside timed intervals. Keep original arrays immutable during capture. Inspect Numba signatures and typed IR to annotate every arithmetic node relevant to an alternative backend.

Use a small profile to choose the first island; longwave primary is the nominated island, not a requirement to port a non-bottleneck. If it is minor, select one other measured island and amend the boundary record before implementation. Current SLEEF functions and input guards stay outside the first island.

## B7-10: implement B before claiming a framework win

Provide a Numba control using the same pixel-major, patch-major or AoSoA layout proposed for C. Both patch sweeps remain sequential within each pixel. Benchmark conversion plus reduction and wrapper boundaries. If B obtains the desired gain without another dependency, that is a valid preferred solution.

Do not wait for B to finish before all useful work: native/Dr.Jit workers can implement the agreed mathematical boundary in parallel. They must compare their final C against frozen B, not a moving branch or an intentionally weak baseline.

## B7-20 to B7-24: independent small backend tracks

Initial tracks: native SIMD (ISPC, or Highway if the verified local toolchain is a better fit), Dr.Jit LLVM, and conditional PoCL CPU. Limit unrelated experimentation, not the number of independent agents. Shared contract, one common immutable corpus, isolated scratch/worktree and dependency environment for each backend. Do not mutate the oracle environment.

Each worker executes: capability check -> compile/import probe -> real reducer on tiny inputs -> typed/bitwise differential -> negative/guard tests -> generated-code explanation -> one small kernel+adapter measurement under the lab lease. A mathematical or runtime failure becomes a narrowed proved domain or rejection, not relaxed tolerance.

MLX CPU/Halide gets a separate pointwise island only if a measured residual is large enough. Never rewrite all rays into a huge tensor graph just to make a library applicable. GPU probes are optional research records outside the CPU selection path; no device auto-selection.

## B7-30 to B7-32: independent acceptance and selection

Review each immutable variant and its proof/counterexample/evidence. The author is not their own reviewer. Reuse valid executions instead of rerunning the whole suite. Performance owner runs independent-process A/B/C comparisons, synchronized boundary timings, then small full-chronology and multi-tile trials. Control interleaved trial order, effective thread pools, cache state, inputs, outputs, and host interference.

Promote only if backend+adapter cost is meaningfully better than B, and the actual user-visible scope improves against both A and B. A kernel-only win is not sufficient. Suggested small-development materiality thresholds live in `BENCHMARK_PROTOCOL.md`; freeze or justify changes before seeing variant results. Close unsuccessful backend tasks with reasons and keep only compact reproducible experiments, not dead production dependencies.

## B7-40 to B7-42: integrate one winner

The integrator alone modifies shared dispatch, package metadata, simulation/cache/checkpoint identities and lifecycle handling. Initially expose a private explicit CPU-backend selection without changing public signatures/defaults. Build one selected backend's optional package/extra; import absence must leave the complete core usable. Missing backend versus unsupported input versus numerical failure must remain distinct.

Preserve seven reducer columns at first. Preserve full public diagnostic functions, current scalar casts, raw visibility and low-level errors through the reference path. Record capability, ISA, compiler, flags, math profile, kernel version, admission coverage and selected layout. Do not share generic cached results across incompatible devices/profiles. Handle cancellation after draining async work, output buffer leases, repeated tile release and memory retirement.

A backend may be qualified only on the actual local OS/ISA. Compile-only checks elsewhere do not prove numerical portability. No new large multi-platform CI matrix is required; preserve current slim required checks.

## B7-50 to B7-53: finish without endless testing

Freeze selected source, built artifacts, environment, runtime envelope and actual final workload. Run the installed optional-backend small TIFF path AND a core-only environment without that dependency. Reuse identical prior tests through transitive dependency hashes.

One final candidate campaign is allowed only when its actual target data and required references are available. No per-backend 1024 campaign, no mandatory 1024 warmup, no full new upstream matrix. Include import, first-use JIT as appropriate, adapters, exports, output/checkpoint validation and durable completion. A single causal corrective retry follows a retained failure and small reproducer, not a blind rerun.

Final records distinguish `backend_comparison_complete`, `integrated_optional_backend`, `retained_numba_no_winner`, `actual_target_unverified` and `actual_24_tile_target_demonstrated_once`. Reaching the first does not imply the last. Leave the same branch unmerged and unpushed by this task. Stop after a justified selected portfolio; do not implement all twenty frameworks because tokens are available.
