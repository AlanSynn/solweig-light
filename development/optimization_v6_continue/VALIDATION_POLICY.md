# Lean validation with an honest final spatial target

## Evidence classes

Keep untouched original upstream, explicitly patched upstream, frozen accepted v5, new candidate, abstract arithmetic checks, structural source observations and hypothetical performance models separate. This packet is source inspection + design + tested helper code, not a numerical qualification. Existing accepted failures remain failed/dispositioned, not silently passed. No weakened tolerance, dropped failing fixture, or candidate-derived golden.

## Tiers and triggers

| Tier | Typical size/work | Trigger and owner |
|---|---|---|
| L0 | tiny state machines, guards, bit patterns, schema/ownership rules | coherent logical change; worker |
| L1 | actual untouched vs candidate kernel, normally 16-128 square, adversarial schedules | one completed kernel change; worker |
| L2 | real 64/128-square TIFF-to-TIFF, complete 24/48 chronological records, 153 target patches | family interactions/integration; numerical reviewer/evidence owner |
| L3 | 128/256-square, a few distinct tiles, compact worker/thread shortlist | candidate selection; single lab owner |
| L4 | actual 24 spatial tiles at target size, each 24 timesteps | only immutable final candidate, single campaign |

A smaller spatial DEVELOPMENT fixture is not a lower-resolution FINAL algorithm. Retain original patch count, physical equations, ray and edge semantics and full chronological dependencies. Small arrays can use long/adversarial ray schedules and raw fallback to exercise scale-dependent indexing without a 1024 simulation. No per-worker/per-commit 1024 admission. A 512 probe is exceptional and must answer a specific scale-only question that smaller tests cannot.

Do not run the complete suite after every edit. Run relevant tests after a coherent patch, family suite after family changes, affected integration tests after combined changes, and a genuine non-skipped small CPU-only TIFF path before final qualification. Numerical mocks may not replace this path; labeled service mocks are allowed for optional acquisition. Packaging changes require installed-wheel tests; otherwise avoid repeating wheel builds until source settles.

## Dependency-aware reuse

Reuse prior evidence only when code dependency closure, fixture/reference data, math/compiler/environment, test harness and affected execution policy are unchanged. A docs-only commit need not invalidate numerics. A shared helper change invalidates its consumers. A block change requires block invariance evidence; a native-thread change requires actual mask and thread-invariance checks. Reusing a mismatched math profile because final values are close is forbidden.

Review existing evidence before reexecuting it. Reviewers are independent of implementers, but should not repeat all passing commands for reassurance. Preserve concise structured terminal evidence and full logs in files. Counterexamples get small fixtures, not a repeated full large run.

## Numerical scope

Metadata, dimensions, output set, dtype, nonfinite/sentinel masks and exact categorical fields are checked before continuous errors. For new exact v5-to-v6 transformations preserve finite bits and signed zeros, NaN/+Inf/-Inf masks and raw codec payload bits as appropriate. Retain original upstream comparison budgets unchanged. Compare all carried state at EVERY small timestep and the affected intermediate fields; final output equality alone can conceal transient differences.

A reduced private demand profile is validated against all demanded original fields. Full public diagnostic entry remains fully tested. A diagnostic omitted by contract is `not_requested`, not an equal zero. Enabling detailed traces may deliberately select the full path and must not be mixed with production timing. Warnings, np.seterr behavior, unsupported errors and alias-driven mutation have explicit guard/fallback tests.

## Development performance

Freeze a small tuning/evaluation split and the selected CPU envelope before selecting a variant. Two or three alternating pairs on small cases are normally sufficient for triage, not for a broad confidence claim. Record raw elapsed values, process/thread settings, routes, cache/JIT states, actual input manifest, output checks and memory. Measure current accepted v5 under the same conditions; no need to run slow original upstream for every speculative patch.

Profiler/counters and uninstrumented measurements are separate. A Python wrapper's self/cumulative time can include native work; it is not a CPU-service decomposition. No other local builds/tests/profilers on the timed host. Preserve actual CPU/RAM/disk limits during all tests. Different CPU budgets produce separate comparison cells.

## Final-only campaign

Freeze protocol BEFORE the run: 24 spatial target tiles, true extents/overlap/physical resolution, 24 records each, 153 patches, outputs, checkpoint=1 or unchanged explicitly selected prior policy, own-met workflow, source/wheel/profile, CPU/RAM/storage, cache regime and start/end boundaries. Count spatial tiles separately from bands and scenes.

Default final new candidate budget: one campaign. No separate mandatory 1024 warmup. Reuse valid existing numerical reference artifacts. New full-size baseline runs default zero; permit one justified missing-reference capture in the final phase only, or report large numerical comparison unverified. The two old references do not cover 22 new tiles. Synthetic replications are useful load tests but not the actual-target dataset.

The timer starts before application imports/JIT/setup needed for the frozen first-use mode and ends after all required artifacts are durably published. Offline post-run evidence analysis may be outside that timer if separately declared; application cache/input validation, required exports and checkpointing remain inside. Include monitored whole workflow as well as named diagnostic inner timers; never relabel one as the other.

One causal retry is preauthorized: retain failed/censored original; locate cause; create small reproducer; fix; pass affected small gates; freeze new source/config; rerun one campaign. Further campaigns are not automatic merely because model tokens are unlimited.

A single successful run can say `actual_24_tile_target_demonstrated_once` only if all 24 target jobs completed, numeric/artifact coverage is actually qualified as required, and the fixed resource/time contract passed. Missing reference/data/hardware leaves the affected claim unverified. Do not claim p95/reliability, robust scaling or full P7/P8 release completion from one campaign. No automatic original-upstream/tuned-CPU/GPU/Linux/default3600/hosted-CI matrix is added here.

## Incomplete or failing outcomes

Keep the best independently verified branch changes. Record the residual phase model and exact unverified/failed gate. Do not stop at imports or stubs, but do not run infinite expensive attempts either. The original 1800-second spatial objective must not be redefined to two cases. A one-pass throughput observation without enough large reference coverage is reported as such, not a combined verified-target success.
